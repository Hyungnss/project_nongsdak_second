================================================================================
농스닥 — 농수산물 가격 분석 파이프라인
================================================================================

KAMIS 일별 소매가격(2016~2025)과 기상 데이터로 네 가지 질문에 답하고,
결과를 웹페이지 한 장으로 만든다.

  Q1  품목별 가격에 계절 패턴이 있는가. 1년 중 언제 싸고 언제 비싼가.
  Q2  기온과 강수량은 가격 변동과 어떤 관계를 보이는가.
  Q3  10년간의 가격 상승은 소비자물가 상승으로 얼마나 설명되는가.
  Q4  과거 가격 분포를 기준으로 현재 가격의 수준을 판단할 수 있는가.




--------------------------------------------------------------------------------
1. 빠른 실행
--------------------------------------------------------------------------------

원본 CSV를 data/raw/ 에 넣고 kamis 폴더에서 아래를 순서대로 실행한다.

    cd HS-project1/kamis

    python 00_merge.py
    python 02_preprocess_a.py
    python 02_preprocess_b.py
    python 02_preprocess_c.py
    python 02_preprocess_d.py
    python 02_preprocess_e.py
    python 03_weekly.py
    python 05_merge.py

    python 11_merge_monthly.py     # 월별 자료가 있을 때만
    python 09_analyze.py all       # 주별 · 월별 · 일별 있는 것 다
    python 10_dashboard.py

    python 14_year_rise.py         # 가장 크게 오른 해 (단독, 02_e 만 있으면 됨)
    python 15_weather_vs_rise.py   # 그 상승이 날씨 탓인지 물가 탓인지 (14 다음)

끝나면 reports/dashboard.html 을 더블클릭한다.
화면 맨 위에서 주별 · 월별 · 일별을 갈아 끼울 수 있다.

주별만 할 거면 11_merge_monthly.py 를 건너뛰고
09_analyze.py 를 인자 없이 실행하면 된다.
서버도 인터넷도 필요 없다. USB로 옮기거나 메일로 보내도 그대로 열린다.

필요한 패키지

    pip install pandas numpy matplotlib pyarrow

pyarrow 가 없어도 돌아간다. 다만 parquet 대신 csv 로 주고받아 느리고 용량이 크다.


--------------------------------------------------------------------------------
2. 실행 순서
--------------------------------------------------------------------------------

각 단계는 바로 앞 단계가 만든 파일만 읽는다.
중간에 멈췄으면 그 지점부터 이어서 돌리면 된다.

  data/raw/*.csv
    |
    +-- 00_merge.py            연도별 CSV 통합      -> price_merged
         |
         +-- 02_preprocess_a.py   컬럼 정리         -> price_a
              +-- 02_preprocess_b.py  소매만 남김   -> price_b
                   +-- 02_preprocess_c.py 결측 제거 -> price_c
                        +-- 02_preprocess_d.py 날짜 -> price_d
                             +-- 02_preprocess_e.py 단위 -> price_e
                                  |
                                  +-- 03_weekly.py  주별 평균 -> price_weekly
                                       |
                                       +-- 05_merge.py 날씨 결합
                                                      -> price_weather_weekly

세 주기가 09_analyze.py 로 모인다.

  [주별] data/processed/price_weather_weekly     05_merge.py 가 만듦
  [월별] data/raw/월별가격.csv + 월별날씨.csv
           -> 11_merge_monthly.py -> price_weather_monthly
  [일별] data/processed/price_day.csv            팀원이 만들어 둔 것 (merge 완료)

        +-- 09_analyze.py [week|month|day|all]
        |      -> dashboard_data_week.json
        |      -> dashboard_data_month.json
        |      -> dashboard_data_day.json
        |
        +-- 10_dashboard.py
               -> reports/dashboard.html   (있는 주기를 모두 담아 전환 가능)

주의 — 02_b 와 02_c 는 계획서에 적은 순서와 반대다.

    계획서:  02_b 결측 제거   /  02_c 소매만 남기기
    실제:    02_b 소매만 남김  /  02_c 결측 제거

파일 체인이 a -> b -> c -> d -> e 로 이어져 있으니 위 순서대로 돌리면 정상이다.
둘 다 필터라 순서를 바꿔도 최종 결과는 같다. 계획서 문서만 실제에 맞춰 고치면 된다.


--------------------------------------------------------------------------------
3. 폴더 구조
--------------------------------------------------------------------------------

    HS-project1/
    |
    +-- data/
    |   +-- raw/           원본 CSV를 여기 둔다 (직접 준비)
    |   +-- processed/     스크립트가 만드는 중간 · 최종 파일
    |
    +-- reports/
    |   +-- figures/       png 그림 (06_baseline, 07_weather, 08_cpi 가 생성)
    |   +-- dashboard.html 최종 웹페이지          <- 이걸 열면 된다
    |
    +-- kamis/             분석 스크립트 (이 폴더)
    +-- service/           FastAPI 웹서비스 (선택)

data/ 와 reports/ 폴더는 스크립트가 알아서 만든다. 미리 만들어 둘 필요 없다.

각 단계는 parquet 과 csv 를 함께 남긴다.

    parquet   다음 단계가 읽는 파일. 빠르고 작다. 사람은 못 읽는다.
    csv       눈으로 확인하는 용도. 엑셀로 열린다.

단계마다 csv 가 남으므로 어디서 값이 틀어졌는지 되짚을 수 있다.

02_preprocess_e.py                                    단위 정규화 (단가 계산)
................................................................................

기능   품목마다 조사 단위가 다르다 (배추 1포기 / 쌀 20kg / 미나리 100g).
       단위크기로 나눠 1단위당 가격을 구하고, 무게 단위는 kg 으로 맞춘다.

       kg 계열과 개수 계열(마리 · 포기)은 성격이 달라 unit_base 로 구분해 둔다.
       고등어 1마리가 몇 kg인지는 원본에 없어서 서로 환산하지 않는다.

       같은 품목 · 품종인데 단위가 2개 이상이면 unit_mismatch 로 표시한다.
       지우지는 않는다. 03_weekly.py 에서 뺄지 판단한다.

입력   price_d.parquet
출력   price_e.parquet / price_e.csv

추가 컬럼   unit_price  1단위당 가격 (무게 단위는 원/kg)
            unit_base   "kg" 또는 개수 단위명 그대로
            unit_mismatch  단위가 섞인 품목·품종 표시

기능   주별 전국 날씨를 year + week 로 붙인다.

       data/processed/price_weather_weekly.csv

기능   네 질문을 모두 계산한다. 결합된 파일 하나면 돌아간다.
       06_baseline.py 등 다른 스크립트를 먼저 돌릴 필요 없다.

       계산의 뼈대 — 물가도 계절도 걷어내지 않는다 (Q3 만 예외)

         가격지수 = 그 주 가격 / 그 상품의 전체 기간 중앙값
         평년값   = 그 주차의 가격지수 중앙값 (여러 해)      <- 계절 모양

         '전체 기간 중앙값' 하나로 나누는 것이 핵심이다.
         해마다 다른 값으로 나누면 물가상승이 지워지지만,
         기간 전체를 같은 수로 나누므로 물가상승이 그대로 남는다.
         단위가 다른 상품끼리 견주려고 1.00 기준으로 맞추는 것뿐이다.
         상관계수(Q2)와 백분위(Q4)는 상수로 나눠도 값이 안 변하므로
         원 가격으로 계산한 것과 결과가 같다.

         Q1 은 '평년값' 자체가 답이고
         Q2 는 가격지수와 날씨를 바로 견주며
         Q4 는 지금 값이 과거 같은 자리 분포의 어디인지를 본다
         Q3 만 원 단위 가격과 물가지수(CPI)를 쓴다

         걷어내지 않은 대가 (보고서에 반드시 적을 것)
           Q1  계절 진폭에 10년치 물가상승이 섞여 실제보다 커진다
           Q2  계절이 기온과 가격을 함께 움직인 몫이 상관에 들어 있다
               (그래서 판정선이 Q2_WEAK_LINE 0.35 / Q2_STRONG_LINE 0.50)
           Q4  최근 값이 위쪽에 몰려 뭐든 '비쌈' 쪽으로 기운다

입력   week   data/processed/price_weather_weekly.parquet   (05_merge.py)
       month  data/processed/price_weather_monthly.parquet  (11_merge_monthly.py)
       day    data/processed/price_day.csv                  (팀원 제작)

       data/raw/cpi.csv     Q3 에만 필요. 없으면 Q3만 건너뛴다.

       입력 파일이 없는 주기는 건너뛰고 마지막에 무엇을 건너뛰었는지 알려 준다.
       한 주기가 실패해도 나머지는 계속 돈다.

출력   data/processed/dashboard_data_<주기>.json  <- 10_dashboard.py 가 읽는다
       data/processed/q1_season_<주기>.csv     계절 진폭 · 싼 달 · 비싼 달
       data/processed/q2_weather_<주기>.csv    기온 · 강수 시차 상관
       data/processed/q3_inflation_<주기>.csv  품목별 명목 · 실질 상승률
       data/processed/q4_position_<주기>.csv   현재 가격의 과거 분포 위치

컬럼 이름
       팀원이 만든 파일은 컬럼 이름이 다를 수 있다.
       한글·영문 어느 쪽이든 표준 이름으로 바꿔 읽는다.
       실행하면 "컬럼 인식: 품목명 -> item_name" 처럼 무엇을 어떻게 읽었는지 찍는다.
       못 찾으면 실제 컬럼 목록을 보여 주고 멈춘다.

10_dashboard.py                                                  웹페이지 생성
................................................................................

기능   분석 결과를 웹페이지 한 장으로 만든다.
       CSS · JS · 데이터를 전부 파일 안에 넣어 자립형이다.
       그림은 그 자리에서 SVG 로 그려서 60KB 안팎으로 가볍다.

       화면 구성
         Q1  평년 밴드차트 · 계절 달력 히트맵 · 계절 진폭 순위
         Q2  뚜렷한 상품 목록 · 시차 곡선(행 클릭) · 폭염/호우 이후
             (계절을 걷어내지 않은 값으로 비교한다)
         Q3  물가지수 추이 · 명목 vs 실질 막대 · 물가 설명 비율
             (물가로 설명되는 몫을 낼 수 없는 품목은 표에서 뺀다.
              명목이 내렸거나 거의 오르지 않아 몫이 999% 로 튄 자리들이다.
              몇 개를 뺐는지는 표 위에 적는다.)
         Q4  판정 분포 · 상품별 백분위 게이지
             (물가를 걷어내지 않아 위치 열은 하나뿐이다.
              예전의 '계절 위치 / 명목 위치' 두 열은 값이 같아져 합쳤다.)

       화면 맨 위에서 일별 · 주별 · 월별을 갈아 끼운다.
       세 주기를 나란히 보면 결론이 주기에 흔들리는지 바로 보인다.
       주기 단추와 Q1~Q4 차례는 스크롤을 내려도 맨 위에 붙어 있다.

       찾아보기 (상품이 수백 개여도 원하는 것만 골라 본다)
         · 평년 밴드          품목·품종 검색 -> 목록이 그것만 남는다
         · 계절 진폭 순위     품목·품종 검색
         · Q3 명목 vs 실질    품목 검색

5. 세 가지 주기 — 주별 · 월별 · 일별
--------------------------------------------------------------------------------

같은 분석을 세 주기로 돌린다. 대시보드 맨 위에서 갈아 끼우며 비교한다.
화면에는 일별 · 주별 · 월별 차례로 놓인다 (촘촘한 것부터).

  주기   계절 칸   시간 축   시차 범위   최소 관측   사건 관찰
  ----   -------   -------   ---------   ---------   ---------
  일별   52 주     일        0~28 일     200 회      28 일
  주별   52 주     주        0~8 주      52 회       4 주
  월별   12 달     달        0~3 달      24 회       3 달

왜 주기마다 값이 조금씩 다른가

  같은 자료라도 묶는 단위가 다르면 결과가 완전히 같지는 않다. 정상이다.

    · 월별은 한 달을 하나로 뭉개서 짧은 등락이 사라진다.
      대신 잡음이 적어 큰 흐름이 또렷하다.
    · 일별은 하루하루가 살아 있어 반응 시점을 잘게 볼 수 있다.
      대신 잡음이 많아 상관이 낮게 나오기 쉽다.
    · 주별이 그 중간이다.

  중요한 건 "세 주기에서 같은 결론이 나오는가" 다.
  세 주기가 모두 "배추는 8월에 비싸다" 라고 하면 믿을 만한 결론이고,
  한 주기에서만 보이는 신호는 묶는 방식이 만든 착시일 수 있다.

  보고서에는 이렇게 쓰면 된다.
    "주별 · 월별 · 일별 세 방식으로 나눠 분석했고, 결론은 세 방식에서 일치했다."

일별의 계절 평년값은 왜 '주차' 로 내는가

  하루 단위로 10년치 평년값을 내면 한 칸에 10개뿐이라 들쭉날쭉하다.
  그래서 계절 모양은 주차(52칸)로 내고,
  시간 축과 시차만 하루 단위로 둔다. 잡음은 줄이고 시점은 잘게 본다.

       년월 = 2016-01
       연도 + 월
       연도 = 2016            (연간 자료)
       year + month
       기간 = 2016년 01월

     값 컬럼은 총지수 / 소비자물가지수 / 지수 / cpi / index 중 아무거나.

     실행하면 "가로형으로 읽습니다 (시점 컬럼 116개)" 처럼 어떻게 읽었는지 찍어 준다.
     그 줄만 확인하면 제대로 읽혔는지 바로 안다.

     끝 해가 덜 찼으면 (예: 2025년이 8월까지) 경고를 찍는다.
     그 해 연평균은 가을·겨울이 빠져 계절에 치우친다.
     상승률이 실제보다 크거나 작게 나올 수 있으니 보고서에 밝혀야 한다.

9. 자주 걸리는 문제
--------------------------------------------------------------------------------

"CSV 가 없습니다: .../data/raw"
    원본 CSV를 data/raw/ 에 넣지 않았다.

"먼저 XX.py 를 실행하세요"
    앞 단계를 건너뛰었다. 2번 실행 순서를 따라 앞에서부터 돌린다.

"parquet 저장 실패"
    pyarrow 가 없다. csv 로만 저장되고 다음 단계도 csv 를 읽으니
    그대로 둬도 돌아간다. 느린 게 싫으면 pip install pyarrow.

"기상 컬럼 avg_tmp 가 없습니다"
    05_merge.py 가 날씨를 못 붙였거나 컬럼명이 다르다.
    05_merge.py 의 WEATHER_VALUES 를 실제 컬럼명에 맞춘다.

"관측 52주 이상인 상품이 없습니다"
    자료 기간이 짧거나 필터가 너무 많이 걷어냈다.
    09_analyze.py 의 MIN_OBS 를 낮춘다.

"월별 가격 파일이 없습니다" / "월별 날씨 파일이 없습니다"
    파일명이 다르다. 11_merge_monthly.py 의 PRICE_FILE · WEATHER_FILE 을 고친다.

"꼭 필요한 컬럼이 없습니다: [...]"
    팀원 파일의 컬럼명이 예상과 다르다.
    메시지에 실제 컬럼 목록이 함께 나오니, 그 이름을
    09_analyze.py 의 ALIASES (또는 11_merge_monthly.py 의 ALIASES) 에 추가한다.

"날씨에 지역이 N개 있습니다"
    월별 날씨가 전국이 아니라 지점·시도별이다.
    그대로 결합하면 같은 달이 여러 행이 되어 가격 행이 배수로 불어난다.
    지역별로 쓰려면 sido_name 과 매핑해 결합 키에 넣어야 한다.

"일별 분석에는 날짜가 필요합니다"
    price_day.csv 에서 날짜를 못 찾았다.
    다음 둘 중 하나면 된다.
      - date / 날짜 / 일자 / 가격등록일자 같은 날짜 컬럼 하나
      - year + month + day 세 컬럼 (이 경우 자동으로 조립한다.
        실행하면 "날짜: year + month + day 로 조립" 이라고 찍힌다)

"temp: 시차 상관이 전부 비어 판정 못 한 상품 N개"
    오류가 아니라 알림이다. 그 상품은 짝지을 관측이 MIN_PAIRS 보다 적어
    기온·강수량 판정에서만 빠진다. Q1 · Q3 · Q4 에는 그대로 들어간다.
    N 이 너무 크면 09_analyze.py 의 MIN_PAIRS 를 낮춘다.

"건너뜀 월별  입력 파일 없음"
    그 주기의 입력이 없을 뿐 오류가 아니다.
    있는 주기만 분석하고 넘어간다.

"cpi.csv 이 없습니다"
    Q3 만 안내문으로 바뀌고 Q1 · Q2 · Q4 는 정상 출력된다.
    나중에 파일을 넣고 09 를 다시 돌리면 채워진다.

날씨 매칭률이 낮게 나온다
    05_merge.py 가 보정 전후 매칭률을 둘 다 찍는다.
    보정하면 매칭률이 떨어질 수 있는데 그게 정상이다. 9번 함정 2를 볼 것.

그림의 한글이 깨진다
    한글 폰트를 못 찾은 것이다. 스크립트가 경고를 찍는다.
    Windows 는 Malgun Gothic, macOS 는 AppleGothic 을 자동으로 찾는다.
    (dashboard.html 은 폰트와 무관하다. 브라우저가 그린다.)

10. 반드시 알아야 할 함정
--------------------------------------------------------------------------------

1) 명목 가격으로 10년 분포를 만들면 최근이 늘 비싸게 나온다

   물가가 오른 만큼 최근 값이 상위권에 몰린다.
   Q4 는 요청에 따라 물가를 걷어내지 않으므로 이 쏠림이 그대로 들어 있다.
   화면에도 '위치 70 이상이 몇 %' 인지를 찍어 그 사실을 드러낸다.

   그래서 Q4 의 '비쌈' 은 두 가지를 함께 담은 말이다.
     · 예년 이맘때보다 비싸다
     · 10년 사이 물가가 올랐다
   둘을 가르고 싶으면 물가를 걷어낸 비교(Q3)를 함께 봐야 한다.

2) ISO 주차는 12월 말에 1로 돌아간다

   2018-12-31(월)~2019-01-06(일) 은 ISO로 2019년 1주다.
   그래서 year · month · week 세 개를 함께 써야 구분된다.
   날씨를 붙일 때도 보정이 필요하다 (05_merge.py 의 FIX_ISO_YEAR).

   보정하면 매칭률이 떨어질 수 있는데 그게 정상이다.
   보정을 안 하면 12월 말 주가 같은 해 1월 첫 주 날씨에 붙어 100%가 나오지만
   한 해 어긋난 값이다.

3) Q2 는 계절을 걷어내지 않는다 - 해석할 때 반드시 함께 적을 것

   여름엔 원래 기온도 높고 배추도 비싸다. 계절이 둘을 동시에 움직인다.
   Q2 는 그 동행까지 관계로 세기 때문에 상관의 절대값이 크게 나온다.
   그래서 판정선을 계절을 걷어냈을 때 쓰던 0.2 / 0.3 보다 높인
   0.35 / 0.50 으로 잡았다.

   여기서 말할 수 있는 것은 "실제 가격이 기온 · 강수량과 함께 움직였다" 까지다.
   "날씨가 값을 올렸다" 도 아니고, "그 해 날씨가 유별나서 비쌌다" 도 아니다.
   뒤쪽(그 해 날씨가 유별났는가)을 보고 싶으면 계절을 걷어낸 값으로 다시 재야 한다.
   09_analyze.py 의 run() 에서 평년값(p50)으로 한 번 더 나눈 계열을 만들어
   analyze_q2 가 그것을 쓰게 하면 된다.

4) 같은 품목이라도 품종 · 등급 · 단위가 다르면 다른 상품이다

   갈치 냉동/생물, 상품/중품, 마리/kg 은 가격대가 다르다.
   묶어서 중앙값을 내면 어느 쪽도 아닌 값이 된다.

5) 상관은 인과가 아니다

   r 이 크다고 "기온이 가격을 올렸다" 고 쓰면 안 된다.
   "같이 움직였다" 까지만 말할 수 있다.

6) Q1 이 찾는 것은 '가격이 가장 싼 시기' 뿐이다

   왜 그때 싼지(출하 시기 · 저장 · 수입 · 양식)는 이 자료 안에 없다.
   달력은 "언제 싸고 언제 비쌌는가" 까지만 말해 준다.
   화면에서도 그 이상을 말하지 않도록 단어를 골랐다.
