1

설치

PC 와 휴대폰 둘 다 까는 것을 권한다. PC 로 일하고, 휴대폰으로 알림을 받는다.

방법 A — 명령 한 줄. PowerShell 을 열고 붙여 넣는다.

PowerShell
winget install --id SlackTechnologies.Slack -e

방법 B — 직접 받기. slack.com/downloads 에서 Windows 용 다운로드를 눌러 받은 파일을 실행한다. 설치 화면에서 따로 고를 것은 없고, 끝나면 Slack 이 저절로 열린다.

App Store 에서 Slack 을 검색해 설치하거나, slack.com/downloads 에서 Mac 용을 받는다.

App Store(아이폰) · Play 스토어(안드로이드) 에서 Slack 을 검색한다. 제작사가 Slack Technologies 인지 확인하고 설치한다.

처음 실행할 때 나오는 알림 허용은 꼭 누른다. 수집 실패 알림을 놓치지 않으려면 필요하다.

브라우저에서 app.slack.com 으로 들어가도 된다. 남의 PC 를 잠깐 쓸 때 편하다. 다만 알림은 설치한 앱이 훨씬 잘 온다.

2

가입하고 팀에 들어가기

팀원 대부분은 "초대를 받았다" 쪽만 하면 된다. 워크스페이스는 팀장 한 명만 만든다.

  1. 메일함에서 Slack 초대 메일을 찾는다. 제목에 초대 또는 Join 이 들어 있다.
  2. 메일 안의 지금 가입(Join Now) 버튼을 누른다.
  3. 이름을 적는다. 팀원이 알아볼 수 있게 실명을 권한다.
  4. 비밀번호를 정하거나 Google 로 계속하기를 누른다.
  5. 설치한 Slack 앱을 열고 같은 이메일로 로그인한다. 이메일로 6자리 확인 코드가 오면 그대로 입력한다.
초대 메일이 안 보이면

스팸함 · 프로모션함부터 확인한다. 그래도 없으면 팀장에게 이메일 주소가 맞는지 알려 주고 다시 초대해 달라고 한다. 초대 링크는 기한이 있을 수 있어서, 오래된 메일이면 새로 받는 게 빠르다.

  1. slack.com 에서 시작하기를 누르고 이메일을 입력한다.
  2. 메일로 온 6자리 코드를 입력한다.
  3. 워크스페이스 만들기를 누른다.
  4. 팀 이름을 적는다 — 예: 농스닥
  5. 내 이름과 사진을 정한다. 사진은 건너뛰어도 된다.
  6. 팀원 이메일을 넣어 초대한다. 나중에 해도 된다.
  7. 지금 하고 있는 일을 물으면 그게 첫 채널 이름이 된다 — 예: nongsdaq-dev
  8. 요금제 화면이나 유료 체험 권유가 나오면 무료 플랜을 고르거나 건너뛴다.
팀원을 더 초대하려면

왼쪽 위 워크스페이스 이름 → 사람 초대. 이메일로 보내거나 초대 링크를 복사해 카톡으로 전달할 수 있다.

기본 사용법

메시지 보내기 · 고치기 · 지우기

  • 입력창에 쓰고 Enter 를 누르면 보내진다.
  • 줄을 바꾸려면 Shift + Enter. 그냥 Enter 를 누르면 쓰다 만 글이 보내진다 — 가장 흔한 실수다.
  • 보낸 메시지에 마우스를 올리면 오른쪽에 작은 메뉴가 뜬다. ⋮ 더 보기 → 메시지 편집 / 메시지 삭제
  • 방금 보낸 내 메시지는 입력창이 비어 있을 때 ↑ 를 누르면 바로 고칠 수 있다.

스레드로 답하기 — 가장 중요

메시지에 마우스를 올리고 💬 스레드에서 답장을 누르면, 오른쪽에 그 메시지 전용 댓글 창이 열린다.

원칙: 누군가의 글에 답할 때는 스레드로 단다. 새 주제를 꺼낼 때만 채널에 바로 쓴다. 스레드 창 아래 채널에도 보내기를 체크하면 결론을 채널에도 함께 남길 수 있다.

멘션으로 부르기

  • @ 를 치고 이름을 고르면 그 사람에게 알림이 간다. 예: @김철수 이거 확인 부탁해요
  • @here — 지금 접속해 있는 채널 멤버에게 알림
  • @channel — 채널 멤버 전원에게 알림. 급한 공지에만 쓴다. 남발하면 다들 알림을 꺼 버린다.

반응(이모지) 달기

메시지에 마우스를 올리고 😊 반응 추가를 누른다. "확인했습니다", "좋아요" 같은 짧은 답은 글 대신 반응으로 한다. 채널이 조용해진다.

입력창 위의 서식 버튼(B, I, </> 등)을 눌러도 똑같이 된다.

DM 보내기

왼쪽 목록의 다이렉트 메시지 옆 + 를 누르고 이름을 고른다. DM 목록에서 내 이름을 누르면 나만 보는 대화방이 된다. 링크나 메모를 잠깐 적어 두는 메모장으로 쓰기 좋다.

채널 찾아 들어가기

왼쪽 채널 옆 + → 채널 둘러보기 에서 채널을 골라 참여를 누른다. 공개 채널은 초대받지 않아도 스스로 들어갈 수 있다.

검색

맨 위 검색창에 단어를 넣는다. 사람 · 채널 · 날짜로 좁힐 수 있다. 채널이나 사람에게 빨리 가고 싶으면 Ctrl + K 를 누르고 이름 몇 글자만 친다.

허들 (음성 · 화면 공유)

채널이나 DM 오른쪽 위 🎧 를 누르면 바로 음성 통화가 시작된다. 화면 공유도 여기서 한다. 무료 플랜에서는 1:1 로만 쓸 수 있다. 여러 명 회의는 다른 도구를 쓴다(무료 플랜 참고).

나중에 다시 보기

메시지에 마우스를 올리고 🔖 나중을 위해 저장을 누르면 왼쪽 메뉴의 나중에 목록에 모인다. 지금 당장 답하기 어려운 부탁을 놓치지 않게 해 준다.

Claude Code 붙이기

채널에서 @Claude 를 부르면 Claude Code 가 클라우드에서 우리 GitHub 저장소를 열고 코드를 고친다. 버그 이야기를 하던 스레드에서 그대로 일을 맡길 수 있는 게 장점이다.

  1. 스레드에서 @Claude 로 요청
  2. 클라우드에 작업 세션이 생긴다
  3. 진행 상황이 스레드에 올라온다
  4. 끝나면 나를 멘션해서 알려 준다
  5. View Session 으로 확인, Create PR 로 PR 생성
2026-09 기준 내용이다

화면 이름과 조건은 바뀔 수 있다. 막히면 공식 문서 Claude Code in Slack 을 본다.

준비물 — 쓰는 사람마다 각자

무엇설명
Claude 유료 요금제Claude Code 가 포함된 Pro · Max. 쓰는 사람마다 각자 필요하고, 사용량도 각자의 한도에서 빠진다
GitHub 계정project_nongsdak 은 비공개 저장소라 협업자로 초대받아 있어야 한다
claude.ai/code 로그인같은 Claude 계정으로 한 번 들어가 GitHub 를 연결해 둔다
Slack 계정 연결Slack 안의 Claude 앱에서 내 Claude 계정과 잇는다

Claude 를 Team · Enterprise 요금제로 쓰는 경우는 방식이 다르다(Claude Tag). 여기는 개인 요금제(Pro · Max) 기준이다.

연결하기

  1. Slack 앱 마켓의 Claude 앱 에서 Add to Slack 을 눌러 워크스페이스에 설치한다. 워크스페이스 관리자만 설치할 수 있다.
  2. #nongsdaq-dev 채널 입력창에 아래를 쳐서 Claude 를 초대한다.
    Slack 입력창
    /invite @Claude
    Claude 는 초대된 채널에서만 대답한다. 설치만 하고 초대를 안 하면 불러도 조용하다.

무료 Slack 의 외부 앱 10개 한도에서 Claude 앱도 1개로 센다.

  1. claude.ai/code 에 로그인해 GitHub 를 연결한다. 안내에 따라 GitHub 계정을 잇고 project_nongsdak 저장소를 고른다. 이걸 한 번도 안 하면 Slack 에서 Claude Code is not enabled for your account 오류가 난다.
  2. Slack 과 Claude 계정을 잇는다. 왼쪽 앱 목록 → Claude → 홈(App Home) 탭 → Connect. 브라우저가 열리면 1번과 같은 Claude 계정으로 로그인한다.
  3. 라우팅 모드를 고른다. 같은 홈 탭의 Routing Mode 에서:
    Code + Chat (권장)코딩 요청이면 Claude Code 가, 그냥 질문이면 일반 대답이 나온다
    Code only@Claude 를 부르면 무조건 Claude Code 작업이 된다

쓰는 법

  • 채널에서만 된다. DM 에서 부르면 Claude Code 작업이 시작되지 않는다.
  • 스레드에서 부르는 게 가장 좋다. 스레드 전체를 읽고 맥락을 파악하기 때문이다. 버그를 이야기하던 스레드 맨 아래에서 부르면 설명을 다시 할 필요가 없다.
  • 요청은 무엇을 · 어디서 · 끝나면 뭘 할지를 구체적으로 쓴다. 아래는 쓰는 방식을 보여 주는 예시다.
막연한 요청@Claude 화면 좀 좋게 바꿔 줘
구체적인 요청@Claude 품목 상세 화면에서 오늘 가격 옆에 평년 대비 몇 % 인지 같이 보여 줘. 화면은 webservice/static/index.html, 데이터는 webservice/db.py 에서 온다. 다 되면 PR 만들어 줘.

작업이 끝나면 스레드에 버튼이 붙는다.

버튼하는 일
View Session브라우저에서 작업 전체 내용을 본다. 거기서 이어서 더 시킬 수도 있다
Create PR바뀐 코드로 PR 을 만든다. 작업 하나에 PR 하나
Retry as Code일반 대답이 나왔는데 코딩 작업을 원했을 때 다시 시킨다
Change Repo저장소를 잘못 골랐을 때 바꾼다

이 프로젝트에서 알아 둘 것

  • 클라우드는 우리 PC 의 Oracle DB 와 .env 를 볼 수 없다.코드 · 문서 고치기와 PR 만들기까지는 되지만, 실제 DB 에 붙여 돌려 보는 확인은 안 된다. PR 을 받아 각자 PC 에서 실행해 보고 병합한다. 수집 스크립트 실행 · DB 조회는 맡길 수 없다. DB 로 확인하는 방법은 바로 아래 DB 확인이 필요할 때 에 있다.
  • PR 은 바로 main 에 들어가지 않는다.팀원이 PR 을 보고 병합해야 반영된다. Claude 가 만든 코드도 사람이 만든 코드처럼 리뷰한다.
  • Claude 는 스레드 안의 다른 메시지에 적힌 지시도 따를 수 있다.팀원만 있는 채널에서만 쓰고, 외부인이 들어오는 채널에는 Claude 를 초대하지 않는다.
  • 비밀 정보 규칙은 그대로다.스레드에 인증키를 붙이면 Claude 도 그걸 읽는다.
  • GitHub 저장소만 된다.다른 곳에 있는 코드는 다룰 수 없다.

DB 확인이 필요할 때 — 터미널 Claude Code 와 이어 쓰기

Slack 의 Claude 는 클라우드에서 돌아서 DB 를 못 본다. 하지만 Oracle 이 설치된 PC 에서 도는 터미널 Claude Code 는 DB 에 붙는다. 둘이 실시간으로 대화하지는 못하고, 되는 것과 안 되는 것은 이렇다.

방향되나방법
터미널 → Slack 세션메시지 보내기claude -p "메시지" --cloud <세션ID>
Slack 세션 → 터미널안 됨클라우드 쪽에서 먼저 말을 걸 수는 없다
Slack 세션을 터미널로가져오기claude --teleport — 방법 A
PR 을 사이에 두고시간차 주고받기PR 리뷰 댓글 + Auto-fix — 방법 B
세션 ID 찾기

Slack 스레드의 View Session 을 누르면 열리는 주소 claude.ai/code/session_... 에서 session_... 부분이다. 주소를 통째로 넣어도 된다.

Slack 에서 시킨 작업을 대화 기록 · 작업 브랜치째로 이 PC 에 가져와 이어서 한다. 설명을 다시 할 필요가 없어서 가장 간단하다.

  1. Slack 에서 @Claude 로 코드 수정
  2. 터미널에서 claude --teleport
  3. 대화 기록 · 브랜치가 이 PC 로 넘어옴
  4. DB 에 붙여 실행 · 검증 후 push
  1. Slack 에서 @Claude 로 작업을 시킨다. 끝나면 View Session 을 누른다.
  2. 세션 화면 메뉴의 Open in → Terminal 을 누르면 붙여 넣을 명령이 복사된다.
  3. 프로젝트 폴더에서 PowerShell 을 열고 붙여 넣는다. 세션 ID 없이 치면 목록에서 고를 수 있다.
    PowerShell
    claude --teleport
  4. 대화가 이어지면 DB 가 필요한 일을 시킨다. 예: 이 변경으로 웹서비스 띄워서 실제 DB 데이터로 화면 확인해 줘
  5. 문제없으면 push 하고 PR 을 병합한다.
  • 커밋 안 한 변경이 있으면 먼저 치워 두라고(stash) 물어본다. 가져오기 전에 작업 폴더를 깨끗하게 한다.
  • 가져온 뒤 작업은 이 PC 에만 남는다. 원래 클라우드 세션에는 반영되지 않으니, 그 뒤로는 터미널에서 계속한다.

클라우드 Claude 가 계속 코드를 고치고, 터미널 Claude Code 가 DB 로 검증해 PR 에 리뷰를 남긴다. 둘이 "대화" 하는 것에 가장 가까운 방식이다.

  1. Slack 세션: PR 생성 + Auto-fix 켜기
  2. 터미널: PR 브랜치를 받아 DB 로 검증
  3. 터미널: 결과를 PR 리뷰 댓글로
  4. Slack 세션: 댓글을 읽고 고쳐서 push
  5. 2 ~ 4 반복, 끝나면 사람이 병합

처음 한 번 준비

  • 저장소 관리자가 Claude GitHub App 을 project_nongsdak 에 설치한다. Auto-fix 가 PR 댓글을 받으려면 필요하다.
  • 터미널 쪽 PC 에 GitHub CLI 를 깔고 로그인한다. 터미널 Claude Code 가 PR 에 댓글을 달 때 쓴다.
    PowerShell
    winget install --id GitHub.cli -e
gh auth login

순서

  1. Slack 에서 작업을 시키고 Create PR 로 PR 을 만든다.
  2. View Session 에서 CI 상태 표시줄의 Auto-fix 를 켠다. 세션에 이 PR 지켜보다가 리뷰 댓글 달리면 고쳐 줘 라고 말해도 된다.
  3. 이 PC 의 터미널 Claude Code 에게 시킨다. 예: PR #12 브랜치 받아서 실제 DB 로 검증하고, 문제 있으면 PR 에 리뷰 댓글로 남겨 줘
  4. 클라우드 Claude 가 댓글을 읽고 고쳐서 push 한다. 요청이 애매하면 고치지 않고 세션에서 되묻는다 — View Session 에서 답한다.
  5. 3 ~ 4 를 반복한다. 끝나면 사람이 리뷰하고 병합한 뒤 Auto-fix 를 끈다.
  • 클라우드 쪽 답글은 PR 을 만든 사람의 GitHub 계정 이름으로 달린다. "Claude Code 가 작성" 표시가 붙는다.
  • 병합 충돌은 알아서 못 고친다. 충돌이 나면 세션에 main 기준으로 rebase 해 줘 라고 말한다.

덧붙임 — 터미널에서 클라우드 세션에 한마디 보내기

PR 까지 갈 것 없이 검증 결과만 전하고 싶으면 터미널에서 바로 보낸다. 보내고 끝나며, 답은 View Session 에서 본다. 아래 메시지는 예시다.

PowerShell
claude -p "DB 로 돌려 보니 2026-09-20 행이 비어 있어. 주말엔 축산물만 오니 빈 화면 대신 안내 문구를 보여 줘" --cloud <세션ID>

공통 제약

  • 같은 Claude 계정끼리만 된다.팀원 A 가 Slack 에서 시작한 세션을 팀원 B 의 터미널로 가져오거나 메시지를 보낼 수는 없다.
  • 터미널 쪽은 누군가 PC 에서 Claude Code 를 켜야 한다.클라우드 쪽에서 로컬을 깨울 방법은 없다.
  • DB 검증은 Oracle 이 설치된 PC 에서만 할 수 있다.

무료 플랜에서 알아 둘 것

Slack 은 무료로 쓸 수 있고, 유료 플랜은 기능을 더 열어 주는 방식이다. 이 팀은 무료로 충분하다.

제한영향
메시지 · 파일은 최근 90일치만 보인다중요한 결정은 문서로 옮겨야 한다
외부 앱 연동은 최대 10개수집 알림 웹훅, Claude 앱, GitHub 연동 정도는 넉넉하다
허들은 1:1 만여러 명 음성 회의는 Discord · Google Meet · Zoom 등을 함께 쓴다

무료 플랜 조건은 Slack 정책에 따라 바뀐다. 정확한 내용은 Slack 공식 요금제 페이지에서 확인한다.

참고

자주 막히는 곳

초대 메일이 안 온다

스팸함을 먼저 본다. 없으면 팀장에게 이메일 주소를 확인받고 다시 초대받는다.

로그인했는데 우리 팀 채널이 안 보인다

다른 워크스페이스에 들어가 있는 것이다. 왼쪽 맨 위 워크스페이스 이름(또는 아이콘)을 눌러 농스닥 으로 바꾼다. 초대받은 이메일과 로그인한 이메일이 다른 경우도 많다.

휴대폰으로 알림이 안 온다
  1. 휴대폰 설정 → 앱 → Slack → 알림이 켜져 있는지 본다.
  2. PC 에서 Slack 을 쓰고 있으면 휴대폰으로는 알림이 바로 안 갈 수 있다. 환경설정 → 알림 의 모바일 알림 시점 설정을 확인한다.
  3. 알림 일시 중지(방해 금지) 시간이 아닌지 본다.
예전 메시지가 사라졌다

삭제된 게 아니라 무료 플랜의 90일 제한으로 가려진 것이다.

Enter 를 눌렀더니 쓰다 만 글이 보내졌다

⋮ → 메시지 편집으로 고치면 된다. 줄 바꿈은 Shift + Enter.

@Claude 를 불렀는데 아무 대답이 없다

그 채널에 Claude 가 초대돼 있는지 본다. 없으면 /invite @Claude. DM 에서는 Claude Code 작업이 안 된다.

"Claude Code is not enabled for your account" 라고 나온다

claude.ai/code 에 Slack 과 연결한 같은 계정으로 한 번 들어가 GitHub 연결까지 끝낸다. 다음에 부르면 사라진다. 팀원마다 각자 해야 한다.

작업은 시작되는데 우리 저장소를 못 찾는다

GitHub 에서 project_nongsdak 협업자 초대를 수락했는지, claude.ai/code 에서 그 저장소를 연결했는지 본다. 엉뚱한 저장소를 골랐다면 Change Repo 를 누르거나 요청에 저장소 이름을 적는다.

부록

수집 알림 웹훅 만들기

매일 17시 30분 수집 결과를 #nongsdaq-alerts 로 보내려면 Incoming Webhook 주소가 하나 필요하다. 팀 전체에서 담당자 한 명이 한 번만 만들면 된다. 나머지 팀원은 건너뛰어도 된다.

담당자용 단계 펼치기 8단계 · 설정 화면은 영어
  1. #nongsdaq-alerts 채널을 먼저 만들어 둔다.
  2. api.slack.com/apps 에 들어가 Create New App → From scratch 를 누른다.
  3. App Name 에 농스닥 알림, 워크스페이스는 농스닥 을 고르고 Create App.
  4. 왼쪽 메뉴 Incoming Webhooks → 오른쪽 스위치를 On 으로 켠다.
  5. 아래 Add New Webhook to Workspace → 채널 #nongsdaq-alerts 선택 → 허용(Allow).
  6. 생긴 Webhook URL(https://hooks.slack.com/services/...) 을 복사한다.
  7. 프로젝트 폴더의 .env 에 한 줄 넣는다.
    .env
    SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
  8. PowerShell 에서 테스트 메시지를 보내 본다. ok 가 출력되고 #nongsdaq-alerts 에 글이 뜨면 성공이다.
    PowerShell
    $url  = "여기에_복사한_웹훅_URL"
$body = [Text.Encoding]::UTF8.GetBytes('{"text":"농스닥 알림 테스트입니다"}')
Invoke-RestMethod -Method Post -Uri $url -ContentType "application/json; charset=utf-8" -Body $body
웹훅 URL 은 비밀번호처럼 다룬다

이 주소만 알면 누구나 채널에 글을 쓸 수 있다. .env 에만 두고, 커밋하거나 채팅에 올리지 않는다. 새어 나갔다면 3번의 앱 설정 화면에서 그 웹훅을 지우고(Remove) 새로 만든다.

관리자 승인이 필요하다고 나오면

워크스페이스 설정에 따라 앱 설치에 관리자 승인이 필요할 수 있다. 워크스페이스를 만든 팀장이 승인하면 된다.
