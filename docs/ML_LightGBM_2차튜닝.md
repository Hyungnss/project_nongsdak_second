# LightGBM 2차 튜닝 (2026-11-20)

> 결과만 보려면 [ML.md](ML.md) 의 '한눈에 보기'. 튜닝 방식(검증 기간 · 점수 · 검증과 시험을 나누는 이유)은 [1차 튜닝](ML_LightGBM_1차튜닝.md) 1~4절과 같다.

---

## 1. 2차를 어떻게 정했나

원래 계획은 '1차에서 두 시장 모두 좋아진 설정끼리 조합' 이었다. 그런데 1차 9개 중 **두 시장 모두에서 base 를 확실히(0.005 넘게) 이긴 설정이 없었다** —
조합할 재료가 없다. 그래서 2차는 **1차에서 건드리지 않은 설정**을 같은 방식(base 에서 하나씩만)으로 본다.

## 2. 2차에서 바꿔 본 설정

| 이름 | 바꾼 설정 | 기본 → 바꾼 값 | 뜻 · 기대 |
|---|---|---|---|
| `ff60` · `ff100` | `feature_fraction` (특성 골라 쓰기) | 80% → 60% · 100% | 나무마다 특성 16개 중 몇 %만 무작위로 쓰나. 줄이면 특성 하나에 덜 기대고(다양한 나무), 늘리면 매번 가장 좋은 특성을 쓴다 |
| `nobag` | `bagging_fraction` · `bagging_freq` (표본 골라 쓰기) | 80% → 끔(100%) | 나무마다 표본 80%만 무작위로 골라 학습하던 것을 끄고 전부로 |
| `l2_1` · `l2_10` | `lambda_l2` (규제) | 0 → 1 · 10 | 잎의 답(변화율)이 너무 커지지 않게 누른다. 클수록 보수적 — 우연한 패턴을 덜 외우게 |
| `slower` | `learning_rate` × `n_estimators` | 0.05 × 400 → 0.01 × 2000 | 1차 `slow`(0.02 × 1000)보다 더 천천히, 더 많이. 도매에서만 효과가 있던 slow 를 한 번 더 |

비교 기준은 **1차의 base** (같은 기간 · 자료 · 채점이라 그대로 비교된다). 공용 Mac Studio · CPU 8개 · 총 38분.

## 4. 해석

**한 줄 결론: 2차에서도 두 시장 모두에서 base 를 이긴 설정이 없다 → 기본 설정(base) 유지.**

| 설정 | 도매 | 소매 | 해석 |
|---|---|---|---|
| 천천히 많이 (slow → slower) | 1.069 → 1.064 → **1.062** (계속 좋아짐) | 1.245 → 1.246 → 1.252 (나빠짐) | 도매에선 2 · 4주가 좋아지지만 소매에선 반대. 시간은 2배씩 든다 (285s → 552s) |
| 표본 골라 쓰기 끄기 (nobag) | -0.004 | +0.012 | 도매 1 · 2주만 좋아짐. 소매에선 나빠짐 |
| 규제 (l2) | 0 ~ +0.004 | +0.010 ~ +0.018 | 보수적으로 만들어도 좋아지지 않는다 → 지금 모델이 잡음을 과하게 외우고 있지는 않다 |
| 특성 골라 쓰기 (ff) | 60% · 100% 모두 나쁨 | 100% 는 비슷, 60% 는 나쁨 | 기본값 80% 가 맞다. 60% 는 2 · 4주가 나빠진다 (작년 비교 · 계절 특성이 빠지는 나무가 많아져서로 보인다) |

- 도매와 소매가 **반대로** 움직이는 설정이 많다 — 한 시장에서의 작은 개선(0.005 안팎)은 우연일 가능성이 크다.
  '두 시장 모두 좋아야 채택' 기준이 이런 우연을 걸러 낸다.
- 1 · 2차 15개 설정 모두 **blend 보다는 6~11% 낫다**. 성능은 설정이 아니라 **입력(가격 특성)과 모델 방식**에서 나온다.

## 5. 1 · 2차를 합친 결론

| | 내용 |
|---|---|
| 시험한 것 | 설정 7가지 방향 · 15개 × 도매 · 소매 = 30번 (검증 기간 2022-10 ~ 2024-10) |
| 결과 | 두 시장 모두에서 base 를 확실히 이긴 설정 없음 |
| 채택 | **base (기본 설정) 그대로** — 잎 63 · 최소 사례 100 · 학습 속도 0.05 × 나무 400 · l1 · 특성 80% · 표본 80% |
| 다음 | base 와 blend 를 **시험 기간(2024-10 ~ 2026-10)에서 한 번만** 채점 → 서비스 모델 교체 판단 |
| 나중에 | 도매만 쓰는 설정(slower) · 기간별 설정(1주는 세밀하게, 4주는 보수적으로) |

## 6. 덤 — 튜닝하면 날씨(B · D)도 효과가 있나

[외부 특성 실험](ML_외부특성실험.md)에서 B(+ 전국 날씨 · 물가) · D(+ 산지 날씨)는 기본 설정으로만 돌렸다.
A 만 튜닝하고 비교하면 불공평하다 — 날씨를 넣으면 특성이 16개 → 30~40개로 늘고 상당수가 잡음이라
기본 설정이 잡음까지 외웠을 수 있다. 그래서 **잡음에 강한 설정**(`ff60` 특성 골라 쓰기 · `l2_10` 센 규제)으로 B · D 를 다시 돌려
**같은 설정의 A** 와 비교했다 (검증 기간 · 점수 낮을수록 좋음 · 괄호는 A 대비).

| 시장 | 설정 | A 가격만 | B + 전국 날씨 · 물가 | D + 산지 날씨 |
|---|---|---|---|---|
| 도매 | base | **1.069** | 1.102 (+0.033) | 1.079 (+0.011) |
| | ff60 | 1.084 | 1.103 (+0.019) | 1.096 (+0.012) |
| | l2_10 | **1.069** | 1.108 (+0.040) | 1.074 (+0.005) |
| 소매 | base | **1.245** | 1.264 (+0.019) | 1.263 (+0.019) |
| | ff60 | 1.262 | 1.264 (+0.002) | 1.258 (**-0.005**) |
| | l2_10 | 1.255 | 1.256 (+0.001) | 1.255 (+0.000) |

- **12번 비교 중 11번은 날씨를 넣은 쪽이 같거나 나쁘다.** 유일하게 좋아진 소매 D · ff60 도 -0.005 로 기준에 겨우 걸치고,
  그 점수(1.258)도 A 의 최고(base 1.245)보다 나쁘다.
- 규제를 세게 걸수록(l2_10) B · D 가 A 에 가까워진다 — 날씨를 **덜 믿을수록** 나아진다는 뜻이라, 날씨 특성이 잡음이라는 증거다.
- 4주 뒤만 보면 산지 날씨가 조금 낫다 (도매 0.973 → 0.970, 소매 ff60 1.122 → 1.103). '날씨는 먼 예측에서 힘을 쓴다' 와 맞는 방향이다.
- **결론: 튜닝해도 1~4주 예측에 날씨는 효과가 없다.** '튜닝을 안 해서 날씨가 졌다' 는 아니다. 서비스는 **A(가격만)** 로 간다.

## 7. 다시 돌리기

```
uv run --group ml python -m ml.tune --round 2 --n-jobs 8
uv run --group ml python -m ml.tune --model lgbm_ext --configs base,ff60,l2_10      # B (DB 또는 ml_runs/cache/external.pkl 필요)
uv run --group ml python -m ml.tune --model lgbm_region --configs base,ff60,l2_10   # D
```
