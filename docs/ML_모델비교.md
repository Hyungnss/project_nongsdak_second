# 가격 예측 모델 비교 — LightGBM · XGBoost · 선형 회귀(Ridge) · ARIMA (2026-11-23)

> 결과 요약은 [ML.md](ML.md). 질문: "왜 LightGBM 인가?" — 같은 특성 · 같은 백테스트 · 같은 채점으로 다른 모델 3가지를 돌려 비교했다.
> 기간은 **검증 기간(2022-10-15 ~ 2024-10-14)만** 썼다. LightGBM 보다 0.005 넘게(도매 · 소매 둘 다) 좋은 모델이 없어서
> **시험 기간은 보지 않았다** ([1차 튜닝](ML_LightGBM_1차튜닝.md) 과 같은 규칙).
> 실행: 실험용 머신 · CPU 8개. 실험 코드는 운영 저장소 밖(실험 폴더)에 있고, 비교 반복은 운영 백테스트와 같은 규칙이다 —
> 기준 숫자(LightGBM 도매 1.0687 · 소매 1.2446 · 소매 + 도매 1.2003, blend 1.1939 · 1.3419)가 그대로 재현됐다.

점수 = 1 · 2 · 4주 MASE 중앙값의 평균 (낮을수록 좋음, 1 미만이면 '가격 그대로' 보다 나음). 방향 = 오를지 내릴지 맞힌 비율.

## 2. 모델마다 해석

### XGBoost — LightGBM 과 거의 같고 조금 나쁘다
- 도매 +0.013 · 소매 +0.006 · 소매 + 도매 특성 +0.010. 세 경우 모두 LightGBM 이 조금 낫다. 대부분 **1주**에서 벌어진다 (도매 1.183 → 1.223).
- 도매 2주(1.038 < 1.050) · 방향 맞힘은 XGBoost 가 조금 낫다. 둘 다 같은 '나무를 쌓는 부스팅' 방식이라 큰 차이가 날 이유가 없다.
- 차이의 원인으로 추정하는 것:
  - **설정**: 이 설정은 LightGBM 을 기준으로 정했고(1 · 2차 튜닝), XGBoost 에는 그 값을 옮겨 맞췄을 뿐이다. XGBoost 를 따로 튜닝하면 차이는 더 줄 수 있다.
  - **범주 처리**: 품목코드(100여 개) 같은 범주를 두 라이브러리가 다르게 나눈다.
- **학습 시간은 LightGBM 이 약 25~30% 짧다** (111 vs 149초 · 114 vs 160초 · 129 vs 175초). 2GB 서버에서 매주 학습하는 조건에서는 이 점도 중요하다.

### 선형 회귀(Ridge) — 기준선 blend 보다도 나쁘다
- 도매 1.443 · 소매 1.415 로 blend(1.194 · 1.342)보다 나쁘다. 특히 **1주가 크게 나쁘다** (도매 1.784).
- 추정하는 이유:
  - **조합을 못 배운다**: '최근 2주 급등 + 수확철 + 채소' 처럼 특성끼리의 조합이 가격을 정하는데, 선형 모델은 특성마다 곱하는 수 하나라 이런 조합을 표현하지 못한다. 예측 기간(1 · 2 · 4주)도 다른 특성과 섞이지 않고 더해지기만 한다.
  - **품종 100여 개를 직선 하나로**: 배추와 쌀이 같은 계수를 쓴다 (품목은 원-핫이라 평균 높이만 달라진다).
  - **오차를 제곱으로 센다**: 가끔 있는 폭등 · 폭락에 끌려간다. LightGBM 은 l1(절댓값)이라 덜 흔들린다.
- 규제 세기(alpha = 1)는 튜닝하지 않았다. 다만 차이가 너무 커서 튜닝으로 LightGBM 을 따라잡기는 어려울 것으로 본다.

### ARIMA — 1주는 꽤 하지만 멀리 갈수록 무너진다 (30품종 표본)
- **1주**는 강하다. 도매 30품종에서 1.243 으로 LightGBM(1.282)보다 낫고, 소매는 1.364 로 blend(1.389)보다 낫다. 바로 앞은 '최근 흐름이 조금 이어진다' 만으로 잘 맞는다.
- **4주**는 blend 보다도 나쁘다 (도매 1.223 vs 1.157 · 소매 1.153 vs 1.121). 방향 맞힘도 기간이 길어질수록 떨어진다 (도매 59% → 57%, 소매 54% → 52%). 다른 모델은 반대로 기간이 길수록 방향을 잘 맞힌다.
- 추정하는 이유:
  - **계절을 모른다**: 1년 주기 계절성을 넣지 않은 ARIMA(차분 1번)는 몇 주 뒤를 '지금 흐름의 연장' 으로만 본다. 수확철에 값이 내려가는 것을 모른다. 조사일 기준 1년 주기가 약 250 걸음이라 계절 ARIMA(SARIMA)는 너무 무거워 하지 않았다.
  - **품종마다 따로**: 한 품종의 3년 자료만 본다. LightGBM 은 모든 품종을 한 모델로 배워 '다른 품종에서 본 패턴' 을 빌려 온다.
- 학습은 빠르다 (30품종 18초). 품종 수만큼 모델을 관리해야 하는 운영 부담은 있다.

## 3. 결론 — 발표 '왜 LightGBM 인가' 에 쓸 한두 줄

> 같은 특성 · 같은 백테스트로 XGBoost · 선형 회귀 · ARIMA 와 비교했다. **LightGBM 이 도매 · 소매 모두 가장 좋았고**, XGBoost 는 거의 같지만
> 조금 나쁘고 느렸다. 선형 회귀는 기준선보다도 나빴고, ARIMA 는 1주는 괜찮지만 계절을 몰라 4주에서 무너졌다(30품종 표본).
> 나무 모델이 '품종 · 시기 · 최근 흐름의 조합' 을 배우는 게 핵심이고, 그중 LightGBM 이 조금 더 정확하고 빨라서 썼다.

## 4. 확신이 없는 것 · 한계

- **XGBoost 설정 맞추기**: `min_child_samples 100` 을 `min_child_weight 100` 으로 옮겼다. `reg:absoluteerror` 의 2차 미분(hessian)이 1이라 '사례 수' 와 같다고 보았는데, 라이브러리 안쪽 구현까지 확인하지는 않았다. XGBoost 는 따로 튜닝하지 않았다.
- **Ridge**: 규제 세기 alpha = 1 고정 · 상호작용 항 없음. "제대로 만든 선형 모델" 이라기보다 "같은 특성을 그대로 넣은 선형 모델" 이다.
- **ARIMA**:
  - 30품종 표본이라 우연의 영향이 있다.
  - 차수는 고정 후보 4개((1,1,0) · (0,1,1) · (1,1,1) · (2,1,1)) 중 AIC 로 골랐다 (auto 탐색 아님 — 계획한 방식이고, 시간 문제는 없었다).
  - 학습 창은 최근 750 조사일, 드리프트(추세 상수)는 없다.
  - 'h 일 뒤' 를 '그 사이 조사일 수만큼 걸음' 으로 바꿨다. 주말 · 공휴일 조사 일정은 미리 알 수 있는 달력 정보로 보았다.
  - 한 품종(615/02/大)은 자료가 짧아 표본의 25% 를 '가격 그대로' 로 메웠다 (전체 메운 비율 도매 1.2% · 소매 1.9%).
- **시드 · 반복 1번**: 각 모델은 한 번씩만 돌렸다. XGBoost 와 LightGBM 의 차이(0.006 ~ 0.013)는 작아서 시드를 바꾸면 조금 달라질 수 있다. 다만 세 경우 모두 같은 방향이었다.
- **표본 품종 수**: 검증 기간에 표본이 있는 품종은 도매 114 · 소매 140 이다 (전체 117 · 153 중 철 지난 품종 제외 — 지난 실험과 같은 표본).

## 5. 하지 않은 것 (발표 뒤 과제)

| 모델 | 이유 |
|---|---|
| Prophet | 품종마다 따로 학습 · 설치 부담. 계절을 다루므로 ARIMA 보다 4주가 나을 가능성은 있다 |
| LSTM 등 딥러닝 | 시간 · 설치 부담, 이 정도 자료 크기(품종 100여 개 · 10년)에서 나무 모델을 이길지 불확실하다 |
| SARIMA | 조사일 기준 주기(약 250)가 길어 무겁다 — 주 단위로 묶어 주기 52 로 해 볼 수 있다 |
| XGBoost 따로 튜닝 | 차이가 작아 튜닝으로 뒤집힐 수도 있다. 뒤집혀도 0.01 안팎일 것으로 본다 |
