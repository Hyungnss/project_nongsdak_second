# 가격 예측 모델 (ml/) — 결과 요약

KAMIS 일별 가격으로 **품종별 1주 · 2주 · 4주 뒤 가격**을 예측한다. 이 문서는 **결과만** 모은다 —

### 이름 사전 — 처음 보는 사람용

**기준선** — 학습 없이 공식으로 계산한다. '이것도 못 이기면 모델이 필요 없다' 는 바닥선.

| 이름 | 예측 방법 |
|---|---|
| naive | 오늘 가격 그대로 |
| seasonal_naive | 1년 전(364일 전) 같은 날 가격 |
| seasonal_adjusted | 오늘 가격 × 작년 같은 기간의 변화율 |
| moving_average | 최근 20 조사일 평균 |
| seasonal_profile | 오늘 가격 × 예년 계절 모양에서의 변화율 |
| **blend** | **naive 와 seasonal_profile 의 평균** = 예년 계절 변화의 절반만큼 — **확정 기준선 · 지금 서비스 중** |

**LightGBM 입력 조합 (A~E)** — 모델 · 설정은 같고 **넣은 정보만** 다르다.

| 이름 | 넣은 정보 | 결과 |
|---|---|---|
| **A** | **가격 정보만** — 최근 등락 · 평균 대비 위치 · 변동성 · 1년 중 시기 · 부류 | **가장 좋음 = base 모델** (도매 운영 모델) |
| **A + 도매** (소매만) | A + 같은 품종의 도매 최근 등락(5 · 20일) · 소매-도매 가격 차이 | **소매 운영 모델** (2026-11-23~) — 외부 데이터가 아니라 같은 시장 안의 '먼저 움직이는' 가격 |
| B | A + 전국 날씨(평년과의 차이) + 물가 | A 와 같거나 약간 나쁨 |
| C | B + 예측 기간의 **실제 미래** 전국 날씨 ('예보가 완벽하다면' — 실험용) | A 와 거의 같음 |
| D | A + 산지(시도) 날씨, 30 · 90 · 180일 전까지 | A 와 같거나 약간 나쁨 |
| E | D + 산지의 실제 미래 날씨 (실험용) | A 와 거의 같음 |

**튜닝 설정** — A 의 학습 설정을 바꾼 것. 넣는 정보는 A 그대로.

| 이름 | 바꾼 것 | 뜻 |
|---|---|---|
| base | — | 기본 설정 (잎 63 · 최소 사례 100 · 학습 속도 0.05 × 나무 400 · l1) |
| leaves15 · 31 · 127 | 잎 개수 | 나무 하나가 상황을 몇 갈래까지 나누나 (복잡도) |
| mcs50 · 300 · 1000 | 잎 최소 사례 수 | 과거 사례가 최소 몇 개 있어야 잎(갈래)을 만드나 |
| slow | 학습 속도 × 나무 수 | 0.02 × 1000 — 조금씩 여러 번 배운다 |
| huber | 오차 세는 방식 | 작은 오차는 섬세하게, 큰 오차(폭등 · 폭락)엔 덜 휘둘리게 |
| ff60 · ff100 (2차) | 특성 골라 쓰기 | 나무마다 특성을 몇 %만 무작위로 쓰나 (기본 80%) |
| nobag (2차) | 표본 골라 쓰기 끄기 | 나무마다 표본 80% 대신 전부로 학습 |
| l2_1 · l2_10 (2차) | 규제 | 잎의 답이 너무 커지지 않게 누른다 — 보수적으로 |
| slower (2차) | 학습 속도 × 나무 수 | 0.01 × 2000 — slow 보다 더 천천히 |

### 성적표

**MASE 중앙값** — 품종마다 '모델 오차 ÷ 가격이 그대로일 것(naive) 의 평소 오차' 를 구해 가운데 값.
**1보다 작으면 naive 보다 잘 맞힌 것, 낮을수록 좋다.**

**시험 기간 (2024-10 ~ 2026-10)** — 지금까지의 최종 성적

| 시장 | 기간 | blend (기준선) | LightGBM A (base) | **A + 도매 특성** (소매) | 개선 (blend 대비) |
|---|---|---|---|---|---|
| 도매 117품종 | 1주 | 1.047 | **0.995** | — | 5% |
| | 2주 | 1.038 | **0.958** | — | 8% |
| | 4주 | 0.910 | **0.864** | — | 5% |
| 소매 153품종 | 1주 | 1.229 | 1.192 | **1.158** | 6% |
| | 2주 | 1.177 | 1.102 | **1.053** | 11% |
| | 4주 | 1.071 | 0.984 | **0.966** | 10% |

소매 'A + 도매' 는 2026-11-23 자료로 다시 돌린 시험 기간이라 A 숫자도 조금 다르다 (A 1.195 · 1.099 · 0.983 → 도매 더해 1.158 · 1.053 · 0.966, [도매 특성](ML_도매특성.md)).

- 품종별로 보면 4주 뒤 도매 74% · 소매 73% 의 품종에서 A 가 blend 보다 나았다.
- 1주는 둘 다 1 근처 — 아주 짧은 기간은 '가격 그대로' 가 여전히 강하다. 모델의 힘은 2 · 4주에서 드러난다.
- 가장 어려운 부류는 수산 (수입량 · 어획량 · 환율처럼 가격에 안 보이는 요인이 크다).

**튜닝 (검증 기간 2022-10 ~ 2024-10)** — 점수 = 1 · 2 · 4주 MASE 중앙값 평균

| 시장 | blend | base | 1차 최고 | 2차 최고 |
|---|---|---|---|---|
| 도매 | 1.194 | 1.069 | 1.064 (slow) | 1.062 (slower) |
| 소매 | 1.342 | **1.245** | 1.245 (base) | 1.245 (base) |

도매에서만 좋아지고 소매에선 나빠지는 설정뿐이라 **두 시장 모두 좋아야 채택** 기준으로 base 를 유지한다.

튜닝으로 고른 설정은 **시험 기간에서 한 번만** 채점해 위 '시험 기간' 표에 더한다.

## 주요 결론

1. **학습 없는 기준선(blend)도 꽤 강하다.** 1~4주 뒤 농산물 가격은 원래 맞히기 어렵다.
2. **LightGBM A 는 두 시장 · 세 기간 모두에서 기준선을 이겼다** (3~8%). 다른 2년(검증 기간)에서도 같았다.
3. **날씨 · 물가를 더해도 좋아지지 않았다** — 미래 날씨를 정답으로 줘도, 잡음에 강한 설정으로 튜닝해도 마찬가지. 지난 날씨는 이미 가격에 반영돼 있다.
   날씨는 수확량이 정해지는 몇 달 단위 예측에서 힘을 쓸 가능성이 크다.
4. **튜닝해도 거의 좋아지지 않았다** — 기본 설정이 이미 잘 맞는다. 설정으로 얻는 차이(±0.03)는 입력을 바꿔 얻는 차이(blend → LightGBM, 0.1 이상)보다 훨씬 작다.
5. **효과가 있었던 건 '가격에 아직 반영되지 않은 정보' 였다** — 소매는 도매를 늦게 따라가서, 도매의 최근 움직임이 소매의 다음 주를 알려 준다
   (소매 1주 -6%, 전체 -3%). 날씨(이미 반영됨)와 달리 같은 시장 안에서 먼저 움직이는 가격이다.

## 실행 · 코드

학습 · 실험은 PC(또는 Mac Studio)에서만 하고(`uv sync --group ml`), 서버 이미지에는 들어가지 않는다 (서빙용 `ml/predict.py` 만).

```
uv run --group ml python -m ml.run --market 도매 --models baselines      # 기준선 6종
uv run --group ml python -m ml.run --market 도매 --models naive,blend,lgbm
uv run --group ml python -m ml.tune --round 1 --n-jobs 8               # 튜닝 (검증 기간)
uv run --group ml mlflow ui --backend-store-uri sqlite:///ml_runs/mlflow.db
```

| 파일 | 하는 일 |
|---|---|
| `ml/dataset.py` | DB → 품종별 일별 시계열 → 예측 표본 (기준일 · 기간 · 목표일 · 정답) |
| `ml/baselines.py` | 기준선 — 학습 없이 규칙으로 예측 |
| `ml/features.py` | LightGBM 특성 (가격에서만 만든다) |
| `ml/external.py` | 외부 특성 (날씨 · 물가 — 실험 B~E) |
| `ml/backtest.py` | 시간 순서를 지키는 백테스트 · 지표 |
| `ml/run.py` | 실행 → 결과표 → MLflow 기록 |
| `ml/tune.py` | 튜닝 — 설정 여러 개를 검증 기간에서 비교 |
| `ml/model.py` | 운영 모델 — 매주 학습 · 게이트 · 저장 · 롤백 (`collector/train.py` · `.github/workflows/train.yml`) |
| `ml/predict.py` | 서빙용 매일 예측 — 배포된 LightGBM, 없거나 실패하면 blend |
| `tests/test_ml.py` · `test_ml_external.py` | 목표일 규칙 · 지표 · **누수 방지** 시험 |
