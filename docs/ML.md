# 가격 예측 모델 (ml/)

KAMIS 일별 가격으로 **품종별 1주 · 2주 · 4주 뒤 가격**을 예측한다.
학습 · 실험은 PC 에서만 하고(`uv sync --group ml`), 서버 이미지에는 들어가지 않는다.

```
uv run --group ml python -m ml.run --market 도매 --models baselines      # 기준선 6종
uv run --group ml python -m ml.run --market 도매 --models naive,blend,lgbm
uv run --group ml mlflow ui --backend-store-uri sqlite:///ml_runs/mlflow.db
```

| 파일 | 하는 일 |
|---|---|
| `ml/dataset.py` | DB → 품종별 일별 시계열 → 예측 표본 (기준일 · 기간 · 목표일 · 정답) |
| `ml/baselines.py` | 기준선 — 학습 없이 규칙으로 예측 |
| `ml/features.py` | LightGBM 특성 (가격에서만 만든다) |
| `ml/backtest.py` | 시간 순서를 지키는 백테스트 · 지표 |
| `ml/run.py` | 실행 → 결과표 → MLflow 기록 |
| `tests/test_ml.py` | 목표일 규칙 · 지표 · **누수 방지** 시험 |

**목표일 규칙** — 기준일 t 의 h 일 뒤에 조사가 있으면 그날, 없으면(주말 · 공휴일) **그 뒤 첫 조사일**.

## 2. 전처리

가격만 쓰는 base 모델이라 전처리는 '쓸 데이터 고르기 · 비율로 바꾸기 · 빈 값은 그대로' 가 전부다.
DB 의 원본은 어느 단계에서도 고치지 않는다 — 전처리는 학습 데이터를 만들 때만 한다.

### 한 것

| 단계 | 처리 | 코드 |
|---|---|---|
| 대상 고르기 | 가격이 있는 날만 (0원 · 빈 값 제외 — DB 가 0 을 막고 수집기가 NULL 로 넣는다) | `dataset.load_series` |
| | 품종마다 대표 등급 하나 (`db.list_products` — 상품 우선, 최근 90일 관측이 20번 미만인 등급은 뒤로) | 〃 |
| | 관측이 60일 미만인 품종은 뺀다 | `dataset.frame_to_series` |
| 빈 날 | 주말 · 공휴일을 메우지 않는다. 시계열을 '조사한 날' 만으로 이어 붙인다 | 〃 |
| 크기 맞추기 | 모든 특성을 **로그 비율**로 만든다. 쌀(5만 원)과 깻잎(2천 원)을 같은 눈금으로 | `features.build` |
| | 맞히는 값도 `log(미래 가격 / 기준일 가격)` | `features.target` |
| 결측 특성 | 과거가 짧아 못 구한 특성(작년 값 없음 등)은 NaN 그대로 — LightGBM 이 직접 다룬다 | `features.build` |
| | 0 으로 나눠 생긴 무한대는 NaN | 〃 |
| 범주 | 품목 · 부류는 범주형 | 〃 |

### 하지 않은 것

| 안 한 것 | 이유 |
|---|---|
| 이상값 제거 · 상한 자르기 | 품질 점검(`collector/quality.py`)에서 도매 단위 변경 · 하루 튐 0건. 남은 '시장 변화' 13건(생강 · 팥 · 들깨 · 양파 · 당근)은 실제 가격 흐름이라 모델이 배워야 한다 |
| 표준화 (평균 0 · 분산 1) | 트리 모델은 값의 크기에 영향받지 않는다. 품목 간 크기는 비율로 맞췄다 |
| 빈 날 채우기 | 조사일만 이어 붙여 필요 없다 |
| 계절 품종 잇기 | 배추 가을 · 월동 등은 별개 시계열. 철이 바뀔 때 예측이 끊기는 한계 (과제) |
| 날씨 · 물가 | base 모델은 가격만 쓴다. 아래 '③-1 에서 할 전처리' 참고 |

### 주의 — 백필 행의 빈 열

과거 백필 행(`DATA_SOURCE='kamis_period'`)에는 당일가격 · 평년가격만 있고 1일전 · 1주전 · 1년전 가격 열은 비어 있다.
특성은 이 열을 쓰지 않고 **가격 시계열에서 직접 계산**한다 (작년 값도 364일 전 조사일을 찾아 쓴다). 새 특성도 이 원칙을 지킨다.

### ③-1 에서 할 전처리 (날씨 · 물가를 넣을 때)

| 데이터 | 처리 | 근거 |
|---|---|---|
| 날씨 | 김해시 평균기온 2건(평균이 최저~최고 밖)은 빈 값으로 | 품질 점검 '범위 밖 값' |
| | 관측소 결측 1~3일(8곳)은 앞뒤 값으로 | 품질 점검 '빠진 날' |
| | 일사량은 측정 관측소(67곳)만 쓰거나 제외 | 절반이 빈칸 |
| | 관측소 → 산지 · 시도별로 묶기 | |
| 물가 | 월 값을 일별 표본에 붙일 때 `AVAILABLE_AT <= 기준일` 인 것만 | 발표 전 값을 쓰면 누수 |
| 공통 | 모든 외부 특성은 `AVAILABLE_AT` 기준으로 그 시점에 알 수 있던 값만 | |

## 3. 기준선 (확정: `blend`)

'이것도 못 이기면 모델이 필요 없다' 는 바닥선. 학습 없이 규칙으로 예측한다.

| 이름 | 예측 |
|---|---|
| `naive` | 기준일 가격 그대로 |
| `seasonal_naive` | 목표일 364일 전(같은 요일) 가격 |
| `seasonal_adjusted` | 기준일 가격 × (작년 목표일 / 작년 기준일) |
| `moving_average` | 최근 20 조사일 평균 |
| `seasonal_profile` | 기준일 가격 × 예년 계절 모양(목표일) / 예년 계절 모양(기준일). 모양은 4주마다 그 이전 자료로 다시 만든다 |
| **`blend`** | **`naive` 와 `seasonal_profile` 의 평균** |

**blend 는 '예년 계절 변화의 절반만큼 바뀐다' 는 규칙이다.**
```
오늘 3,000원, 예년엔 4주 동안 20% 내림
  naive            3,000원
  seasonal_profile 3,000 × 0.8 = 2,400원
  blend            (3,000 + 2,400) / 2 = 2,700원   (10% 내림)
```

**왜 blend 인가** (도매, 4주 뒤 MASE 중앙값 — 낮을수록 좋음)

| 부류 | naive | seasonal_profile |
|---|---|---|
| 채소 · 과실 | 0.974 · 1.300 | **0.837 · 1.213** — 제철이 뚜렷하다 |
| 곡물 · 특용 · 수산 | **0.781 · 0.949 · 1.660** | 1.213 · 1.049 · 1.983 — 저장 · 수입 품목은 계절을 덜 탄다 |

강점이 부류마다 갈려서, 둘을 섞으면 어느 쪽에서도 크게 틀리지 않는다.
1 · 2 · 4주 모두 6종 중 가장 좋거나 거의 같았다 (4주 뒤 0.932). 모델은 이 점수를 넘어야 한다.

## 4. base 모델 — LightGBM (가격만)

- **모든 품종을 모델 하나로** 학습한다 (배추에서 배운 패턴을 무에도 쓰게).
- 특성 16개 — 최근 5 · 20 · 60 조사일 평균 대비 위치, 5 · 20 · 60 조사일 수익률, 20 조사일 변동성,
  직전 조사일과의 간격, 작년 · 재작년 같은 기간 변화, 작년 대비 수준, 평년가 대비 수준,
  목표일의 연중 위치(sin · cos) · 요일, 예측 기간, 품목 · 부류
- 설정은 기본값 (`backtest.LGBM_PARAMS`). 시험 기간 결과를 보며 설정을 고치면 점수가 부풀려지므로 아직 튜닝하지 않았다.

## 5. 평가 — 시간 순서를 지키는 백테스트

무작위로 섞어 나누면 미래로 과거를 맞히게 된다. 그래서 **학습은 항상 과거, 시험은 그 직후 4주**로 나누고
4주씩 앞으로 옮기며 반복한다 (walk-forward).

```
1번째:  [ 학습: 2016-01 ~ 2024-10-13 ] → [ 시험: 2024-10-14 ~ 11-10 ]
2번째:  [ 학습: 2016-01 ~ 2024-11-10 ] → [ 시험: 2024-11-11 ~ 12-08 ]
  ...                                          (4주씩 앞으로, 27번)
27번째: [ 학습: 2016-01 ~ 2026-09-15 ] → [ 시험: 2026-09-16 ~ 10-14 ]
```

- 시험 기간은 최근 2년 (최신 조사일 - 35일까지 — 4주 뒤 정답이 있어야 채점한다). 학습은 매번 2016년부터 그 시점까지 전부.
- 학습에는 **그 시점에 정답이 이미 나온 표본만** 쓴다 (목표일 < 재학습 날짜).
- 튜닝을 시작하면 기간을 셋으로 나눈다: 학습 ~2022-10 · 검증(튜닝) 2022-10~2024-10 · 시험(최종 점수, 한 번만) 2024-10~2026-10.

**지표**

| 지표 | 뜻 | 쓰임 |
|---|---|---|
| **MASE 중앙값** | 오차 / 평가 이전 기간 naive 오차. 품종마다 구해 중앙값 | **주 지표**. 가격 크기와 상관없이 품종끼리 비교 |
| MASE 평균 | 같은 값의 평균 | 크게 틀리는 품종이 있는지 (고등어 같은 소수 품종에 끌린다) |
| MAPE | 평균 % 오차 | 사람이 읽기 쉬운 값 |
| DIR | 오를지 내릴지 맞힌 비율 | 화면의 '사기 좋은 때' |

**누수 방지** — 미래 가격을 일부러 10배로 바꿔도 기준일의 기준선 예측 · 특성이 그대로인지 `tests/test_ml.py` 가 확인한다.

## 6. 결과

### 도매 (117품종, 시험 2024-10-14 ~ 2026-10-14, 2026-11-19 실행)

| 기간 | MASE 중앙값 naive → blend → **LightGBM** | MAPE blend → LightGBM | DIR blend → LightGBM |
|---|---|---|---|
| 1주 | 1.045 → 1.037 → **0.995** | 5.2% → 5.0% | 59% → 61% |
| 2주 | 1.045 → 1.024 → **0.958** | 7.8% → 7.4% | 62% → 64% |
| 4주 | 1.081 → 0.932 → **0.864** | 11.0% → 10.1% | 64% → 67% |

부류별 (4주 뒤 MASE 중앙값, blend → LightGBM): 식량 0.943 → 0.716 (**-24%**) · 과실 1.265 → 1.018 (-20%) ·
채소 0.831 → 0.728 (-12%) · 특용 0.987 → 0.872 (-12%) · 수산 1.782 → 1.641 (-8%).
품종 116개 중 86개(74%)에서 LightGBM 이 더 나았다.

- 기준선이 약했던 곡물에서 가장 크게 좋아졌다. 품목마다 '계절을 얼마나 믿을지' 를 스스로 배운 것으로 보인다.
- **수산이 가장 어렵다** (냉동 고등어 · 홍합 · 마른김 · 마른오징어). 가격 흐름만으로는 안 보이는 수입량 · 어획량 ·
  환율의 영향이 큰 것으로 보인다 → ③-1 에서 물가(수산물 지수) 등 외부 특성의 효과를 볼 대상.
